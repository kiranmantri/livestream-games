# Live Games — Design (v2, after review)

## Decisions
- Phrase length 3-5 words, no greetings. Phrase sources: transcript | chat | transcript+chat | manual.
- Corpus work first (tasks 2-3), then app.
- Session ends when the ADMIN finishes it (after some time). The winner is the player with the most
  marked phrase cells (max 24; free centre not counted); tie -> reached that count first; no marks
  -> no winner. (Changed from "first to mark all cells declares BINGO": simulation on the real
  corpus gives 0.0% chance of a full card even after 8 h, ~80% for a single line after 8 h.)
  Honour-based marking; revisit later.
- Admin: `ADMIN_PASSWORD` env, HTTP Basic.

## Data model (PostgreSQL)

    users
      id uuid PK
      session_id uuid FK -> game_sessions
      name varchar(20) NOT NULL
      name_ci text GENERATED ALWAYS AS (lower(btrim(name))) STORED
      ip inet, cookie_token text UNIQUE, created_at, last_seen_at
      UNIQUE (session_id, name_ci)

`name_ci` is the case-insensitive comparison key of the display name. `name` keeps what the
user typed ("Ana"); `name_ci` is the trimmed, lower-cased copy ("ana") that the unique
constraint uses, so "Ana", "ANA" and " ana " collide. Generated by the DB so it cannot drift.
Limitation: `lower()` does not strip accents or normalise Unicode ("José" vs "Jose" are
different); we can apply NFKC/unaccent in the app before insert if lookalike names matter.

    game_sessions
      id uuid PK, game_type text ('bingo'),
      status text ('active'|'ended'),
      created_by uuid FK users, winner_user_id uuid FK users NULL,
      created_at, ended_at
      UNIQUE INDEX ON (status) WHERE status = 'active'   -- one running session

    bingo_cards
      id uuid PK, session_id FK, user_id FK, created_at,
      cells jsonb    -- 25 items; idx 12 = {"type":"image"}; others {"phrase_id","text"}
      UNIQUE (session_id, user_id)   -- assigned once, no update path

    bingo_marks
      card_id FK, cell_index smallint (0-24), marked_at
      PK (card_id, cell_index)       -- score = number of rows; centre (free) is never stored (max 24)

    phrases
      id, text (1-5 words) UNIQUE,
      source text CHECK in ('transcript','chat','transcript+chat','manual'),
      score real, enabled bool default true, created_at

    ingested_videos
      video_id PK, title, width, height, orientation ('horizontal'|'vertical'),
      has_transcript bool, has_chat bool, ingested_at

## Plan (stop after each task for review)
1. Scaffold (uv, pyproject, compose+Postgres, AGENTS.md, .env.example)
2. Corpus fetch: last 5 horizontal streams -> pt auto-captions + live_chat in data/corpus/
3. Phrase extraction + ranked report (1-5 word expressions); user approves; manual additions
4. DB schema + migrations + constraint tests
5. Session/identity services (create/join/resume; cookie + IP)
6. Card generator (random, persisted, immutable)
7. Player UI (join/start, 5x5 card, marking, live leaderboard)
8. Admin page (users, cards, session)
9. Dockerfile + full compose deployment + e2e smoke test

## Risks
Noisy auto-captions (manual approval step); 8-10h streams (slow download, rate limits);
live_chat may be missing/truncated (report, don't skip silently); IP/cookie control is weak;
honour-based marking can be abused (revisit); marks must only be accepted while the session is active (task 7).
